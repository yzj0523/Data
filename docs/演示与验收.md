# AI 问数演示与验收

本记录覆盖 Ticket 03–32 的实现和验证。固定数据版本为 `demo-1`，统计截止日期为 `2026-08-31`。常规自动化测试使用供应商替身。2026-11-18 已完成真实模型演示，Linux 容器运行验收仍待 Q11 提供环境。

## 运行与演示

本地方式见 [后端启动](../backend/README.md) 和 [前端启动](../frontend/README.md)。在 `backend/` 安装依赖后，依次执行 `python -m app.seed`、`python -m app`。在另一个终端进入 `frontend/`，执行 `npm ci`、`npm run dev`，打开 `http://127.0.0.1:5173`。容器方式见 [部署说明](部署.md)。

模型走 OpenAI 兼容的公开 HTTPS 服务。通过 `backend/.env` 配置默认模型，或从「模型配置」测试连接、添加并保存选择，再在「应用配置」启用自定义模型。问答需要模型支持 JSON 对象输出。`/api/health` 的 `not_checked` 表示只确认配置存在。模型连通性需要实际测试。

1. 在「智能问数」选择商业市场台账，问「2026 年北京代表处的确认收入是多少」，核对 **3000 万元**，展开「分析过程」查看执行 SQL、参数、来源、截止日期和模型名称。
2. 用同义问题「北京代表处 2026 年确认收入总额」交叉验证。同会话追问「改成 2025 年」，核对 **2500 万元**。再追问「用饼图」，表格值应保持一致。
3. 提问「按经营单元查询 2026 年政企确认收入在 3000 到 5000 万元之间的记录」，核对上海 **5000 万元**、北京 **3000 万元**。问「2026 年确认收入最高的两个经营单元」，两项顺序相同。
4. 提问「2026 年每月含税签约额趋势，用折线图」，核对一月 **9500 万元**、二月 **1300 万元**。问含税签约额最高的两个月，应为一月 **9500 万元**、三月 **3300 万元**。按月对比 2026 年确认收入和去年同期，一月应为 **6500 / 6300 万元、同比 +3.17%**，二月基期为零，同比不可计算。
5. 仅选择整体目标台账，查询北京代表处 2026 年的商业和商解目标，分别核对 **6000 万元**和 **1000 万元**。再选商业市场台账，查询对应的两种完成率，分别核对 **4800 / 6000 万元、80%**与 **460 / 1000 万元、46%**。缺失的实际金额及对应完成率显示为「不可计算」。
6. 选择 PPL 明细台账，分别问「高风险项目总数」和「列出高风险项目编号和名称」，核对 **3 个**以及 `j1`、`j4`、`j5`。限定 2026 年后，按落地日期得到 **2 个**项目，分析过程说明落地日期缺失的项目不计入。
7. 在历史会话中选择、置顶、重命名和删除会话。编辑较早的问题，替代结果可用后核对旧后续轮次已替换。若查询失败或需要澄清，刷新并核对旧答案仍可见、可反馈。在「回复校对」核对反馈快照、保存处理备注并刷新页面。
8. 将普通提问成功提交四次，查看该题出现在默认阈值为 3 的「常问」。收藏一个问题，刷新后查看收藏。修改应用欢迎文案并新建对话，检查配置应用。

## 独立核对 SQL

在初始化后的 SQLite 数据库执行以下查询。结果金额以人民币分保存，除以 `1000000` 转为万元。进一步的字段说明见 [指标字典](指标字典.md)。

```sql
SELECT d.name, SUM(s.revenue_cents) AS cents
FROM monthly_sales s
JOIN contracts c ON c.id = s.contract_id
JOIN divisions d ON d.id = c.division_id
WHERE s.period >= '2026-01-01' AND s.period < '2026-09-01'
  AND c.industry_group = '政企'
GROUP BY d.id
HAVING SUM(s.revenue_cents) BETWEEN 3000000000 AND 5000000000
ORDER BY cents DESC;

SELECT substr(signed_on,1,7) AS month, SUM(gross_cents)
FROM contracts
WHERE signed_on >= '2026-01-01' AND signed_on < '2026-09-01'
GROUP BY month ORDER BY month;

SELECT strftime('%Y', period) AS year, SUM(revenue_cents)
FROM monthly_sales
WHERE period IN ('2025-01-01','2026-01-01')
GROUP BY year ORDER BY year;

SELECT SUM(net_cents) FROM contracts WHERE division_id='bj' AND signed_on LIKE '2026-%';
SELECT commercial_cents, solution_cents FROM annual_targets WHERE division_id='bj' AND year=2026;
SELECT SUM(net_revenue_cents) FROM monthly_sales
WHERE contract_id IN (SELECT id FROM contracts WHERE division_id='bj' AND is_solution=1)
  AND period >= '2026-01-01' AND period < '2026-09-01';
SELECT id, name FROM projects WHERE risk='高风险' ORDER BY id;
```

## 真实模型演示

2026-11-18 使用 DeepSeek API（`api.deepseek.com`），模型配置名为 `deepseek-flash`。在 Windows 上用 Chromium 打开生产构建的预览页面，Vite 代理请求 Uvicorn。后端使用临时 SQLite 库及 `demo-1` 种子数据。通过独立 SQL 按北京经营单元和统计月份汇总 `revenue_cents`，得到 2026 年 3000 万元、2025 年 2500 万元。浏览器在同一会话选择商业市场台账，按下列顺序提交问题。

| 问题 | 页面结果 | 后端耗时 | 供应商报告的 Token |
|---|---|---:|---:|
| 2026 年北京代表处的确认收入是多少？ | 3000 万元 | 2358 毫秒 | 1346 |
| 北京代表处 2026 年确认收入总额是多少？ | 3000 万元 | 1369 毫秒 | 1363 |
| 改成 2025 年 | 2500 万元 | 925 毫秒 | 1247 |
| 用饼图 | 2500 万元，成功显示饼图 | 1543 毫秒 | 1314 |

四轮结果均与独立 SQL 一致，各轮可查看实际执行 SQL 和数据来源。刷新页面后恢复四轮会话及最后一轮的金额。
